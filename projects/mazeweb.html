MazeWeb

Web-design class: a handheld-style site where JavaScript owns the maze and Unity WebGL draws it — original music stems signal special tiles and the exit.

Play live GitHub

Overview

A full game inside a website made to feel like a toy handheld. JavaScript generates the maze and rules (find every special tile, then the exit). Unity WebGL builds the 3D world from that grid via prefabs. Music I wrote sits in looping stems: a base bed always there, then extra layers that fade in based on how many walkable tiles you are from a special tile or the exit.

Contributions

  • Designed the loop and wrote the maze in JavaScript: random generation, player controls, special tiles, exit, and win state.
  • Unity WebGL as the view: engine reads the JS maze over the DOM/SendMessage bridge and instances prefab tiles to match the grid.
  • Audio: walking SFX timed to movement with slight variation. Original stem music — ambience always on; special and exit layers fade in as you get fewer walkable tiles away (path distance, not a straight line), then fade out when you leave, so the mix tells you what’s close without a UI ping.
  • Handheld shell around that — menus, special-room counter, volume, reset, UX chrome. Used Cursor to implement that UI and some JS↔Unity glue; maze logic, rules, music, and audio direction are mine.

Challenges

Keeping one maze in JavaScript and a matching 3D layout in Unity without the two drifting — plus mixing stem layers so they cue the player without fighting footsteps.

Lessons Learned

Treat JS as the game and Unity as the renderer. Proximity stems did more for “where am I going?” than extra UI. Cursor is part of how I ship chrome and glue; I still own the rules, the music, and what the audio is supposed to do.
